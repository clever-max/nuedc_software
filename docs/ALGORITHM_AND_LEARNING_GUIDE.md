# MSPM0 智能小车算法与工程学习指南

## 1. 文档目的

本文档是当前 MSPM0G3507 小车项目的学习和开发基线，面向两类读者：

- 零基础成员：理解小车为什么能运动、如何循迹、如何停车，以及每个算法解决什么问题。
- AI 和开发成员：按照统一的目录、接口、时序、验证和安全边界修改工程。

本文档不要求一开始掌握所有数学知识。建议先完成最小实验，再逐步理解公式和参数。

本文档中的算法按以下顺序组织：

```text
传感器采集
    -> 数据清洗与标定
    -> 状态估计
    -> 控制器
    -> 电机目标
    -> 电机速度闭环
    -> PWM 输出
```

## 2. 先建立几个基本概念

### 2.1 传感器是什么

传感器把现实世界转换为数字量，例如：

- 编码器：车轮转了多少格
- 灰度传感器：每个探头下方是黑线还是白底
- IMU：当前角度、角速度和加速度
- ADC 角度传感器：摆杆或旋钮对应的电压
- 超声波：前方障碍物的距离

传感器读数不是最终答案。读数必须经过标定、滤波、单位转换和有效性检查，才能交给控制器。

### 2.2 执行器是什么

执行器是程序可以控制的对象：

- 电机 PWM：控制电机施加多大驱动力
- 电机方向引脚：控制前进或后退
- 舵机或云台：控制角度
- 蜂鸣器和 LED：反馈状态

### 2.3 目标值、测量值和误差

以左轮速度为例：

```text
目标速度 target = 500 mm/s
实际速度 measured = 450 mm/s
误差 error = target - measured = 50 mm/s
```

控制器根据误差改变 PWM，使实际速度逐渐接近目标速度。

### 2.4 开环和闭环

开环是“给固定 PWM，猜车速”；电池电压、地面摩擦和负载变化后，速度会改变。

闭环是“测量实际速度，再不断修正 PWM”。小车必须使用闭环，尤其是：

- 单轮速度闭环
- 直行左右轮同步
- 巡线转向闭环
- 角度保持闭环
- 倒立摆平衡闭环

## 3. 系统总体架构

建议将工程划分为六层：

```text
app/          程序入口、运行模式和故障处理
mission/      赛题流程、阶段状态机和路线
control/      PID、LQR、速度控制、巡线和姿态控制
perception/   灰度、IMU、测距、视觉结果和置信度
bsp/          PWM、编码器、ADC、I2C、UART、GPIO、DMA
protocol/     调参、遥控、日志和数据记录
```

依赖方向固定为：

```text
app / mission
        ↓
control / perception / protocol
        ↓
bsp
        ↓
SysConfig 生成代码和 DriverLib
```

上层不应该直接操作 GPIO 寄存器；控制算法不应该知道某个传感器接在哪个具体引脚；SysConfig 生成文件不应该手工修改。

## 4. 电机和编码器算法

### 4.1 正交编码器如何测方向

一个编码器通常有 A、B 两相信号。两相相差 90 度：

```text
A 上升沿时 B 为低 -> 一个方向
A 上升沿时 B 为高 -> 另一个方向
```

最小实现是：

1. A 相上升沿触发 GPIO 中断。
2. 在中断中读取 A、B 当前电平。
3. 根据 A 与 B 的关系给对应计数器加一或减一。
4. 主循环或控制周期读取计数器增量。
5. 读取后清零，下一周期重新累计。

中断中只做计数，不做浮点运算、打印、I2C 和复杂控制。

### 4.2 计数转换成速度

设：

- `delta_count`：一个控制周期内的编码器增量
- `count_per_revolution`：车轮转一圈对应的编码器计数
- `wheel_diameter_mm`：轮径
- `dt`：控制周期，单位为秒

车轮一圈的周长为：

```text
circumference = pi × wheel_diameter_mm
```

本周期位移为：

```text
distance_mm = delta_count / count_per_revolution × circumference
```

轮速为：

```text
speed_mmps = distance_mm / dt
```

所有速度控制接口建议统一使用 `mm/s`，所有时间控制接口统一使用 `s` 或明确标注 `ms/us`。

### 4.3 差速底盘模型

对于左右轮差速小车：

- `vx`：车体前向速度，单位 mm/s
- `wz`：车体偏航角速度，单位 rad/s
- `L`：左右轮中心距，单位 mm

左右轮目标速度为：

```text
v_left  = vx - wz × L / 2
v_right = vx + wz × L / 2
```

这一步很重要，因为巡线算法输出的不是“左轮 PWM”，而应该是“车体需要向哪边转”。底盘控制器再把车体运动需求转换成两个轮子的速度目标。

### 4.4 增量式速度 PID

速度环可以使用增量式 PID：

```text
e[k] = target[k] - measured[k]

Δu[k] = Kp × (e[k] - e[k-1])
       + Ki × dt × e[k]
       + Kd / dt × (e[k] - 2e[k-1] + e[k-2])

u[k] = u[k-1] + Δu[k]
```

工程实现必须包含：

- PWM 输出限幅
- 停车时清空 PID 内部状态
- 电机死区补偿
- 堵转或编码器无脉冲检测
- 左右轮独立参数或左右轮误差补偿

当目标速度接近零时，不能只把目标设置为零，还要清空积分和历史误差，否则重新启动时可能出现突跳。

### 4.5 电机速度闭环的验收

先不要接巡线。只做以下实验：

1. 左轮目标 100 mm/s，记录实际速度。
2. 左轮目标 200、300、500 mm/s，记录稳态误差。
3. 右轮重复相同实验。
4. 左右轮同时 300 mm/s，观察直行偏差。
5. 改变电池电压和负载，观察闭环是否仍然稳定。

至少记录：目标速度、实际速度、PWM、上升时间、稳态误差、过冲和是否饱和。

## 5. 灰度传感器和巡线算法

### 5.1 灰度传感器读取

常见 8 路灰度模块可能通过模拟开关复用一个 ADC：

1. 设置三根地址线，选择通道。
2. 等待模拟电压稳定。
3. 读取 ADC。
4. 丢弃通道切换后的第一笔样本。
5. 保存 8 路结果。

如果使用数字输出，则每个通道直接得到黑/白状态。无论模拟还是数字，都要明确：

- `1` 是黑线还是白底
- 传感器从左到右的顺序
- 传感器间距
- 车体前进方向
- 黑线宽度和传感器高度

### 5.2 标定

模拟灰度至少需要采集：

- 白底值 `white[i]`
- 黑线值 `black[i]`

归一化结果可写为：

```text
normalized[i] = (raw[i] - black[i]) / (white[i] - black[i])
```

实际工程中应限制结果范围，避免除零和异常值：

```text
normalized[i] = clamp(normalized[i], 0, 1)
```

数字化判断建议使用迟滞：

```text
raw > high_threshold -> 判为白
raw < low_threshold  -> 判为黑
中间区域             -> 保持上一次状态
```

迟滞可以避免传感器在阈值附近反复跳变。

### 5.3 位置误差

给每个传感器一个横向位置权重：

```text
[-3.0, -2.7, -2.5, -2.0, 2.0, 2.5, 2.7, 3.0]
```

对于检测到黑线的通道，计算加权平均：

```text
line_error = Σ(weight[i] × line_strength[i]) / Σ(line_strength[i])
```

这样得到的是连续误差，比“左边亮就左转、右边亮就右转”更平滑。

如果没有任何有效通道，不能直接把误差当作 0。应进入 `LINE_LOST` 状态，根据上一次误差、编码器距离和安全策略尝试恢复。

### 5.4 巡线控制

巡线控制器输出车体偏航角速度 `wz`：

```text
wz = line_pid(line_error)
v_left  = base_speed - wz × wheel_base / 2
v_right = base_speed + wz × wheel_base / 2
```

车速越高，巡线 PID 越容易振荡。建议使用速度调度：

```text
直线：较高 base_speed
大误差：降低 base_speed
急弯：进入低速或原地转向
丢线：立即减速并执行恢复动作
```

### 5.5 路口和直角判断

路口判断不能只依赖单帧。推荐流程：

```text
单帧模式识别
    ↓
连续 N 帧确认
    ↓
合并多帧左右边缘状态
    ↓
判断左直角、右直角、十字、丁字或未知
```

每种路口都应有独立的测试样本，不要只在完整赛道上调试。

## 6. IMU、角度和位置估计

### 6.1 陀螺仪角度积分

陀螺仪输出角速度 `omega`，角度更新为：

```text
angle[k] = angle[k-1] + omega[k] × dt
```

必须进行零偏校准：

1. 上电后静止。
2. 连续采样多次。
3. 计算平均零偏。
4. 后续读数减去零偏。

角度误差要归一化到 `[-180°, 180°]`，否则从 359° 到 1° 会被误判成 358° 的大误差。

### 6.2 角度保持

```text
angle_error = wrap(target_angle - current_angle)
turn_correction = heading_pid(angle_error)

left_target  = forward_speed - turn_correction
right_target = forward_speed + turn_correction
```

角度保持适合：

- 直行纠偏
- 90° 或 135° 转弯
- 倒车过程中的方向保持

但单独依赖陀螺仪会产生漂移，应该使用编码器、灰度事件或外部视觉进行阶段校正。

### 6.3 角位移传感器

对于摆杆、云台或角度电位器类传感器，建议独立封装：

```text
raw ADC
  -> 电压
  -> 有效量程标定
  -> 零点补偿
  -> 方向补偿
  -> 单端角度
  -> 相对零点的有符号角度
```

启动自动校准时必须明确机械姿态。例如倒立摆传感器必须在上电时保持竖直。

## 7. 阶段状态机与赛题流程

### 7.1 为什么不能把所有逻辑写在 `main` 中

如果用大量 `if`、计时器和全局变量控制比赛流程，后期会出现：

- 某个计时变量被多个动作共用
- 转弯完成条件不清楚
- 传感器事件与固定时间互相冲突
- 修改一段路线影响另一段路线
- 无法判断当前小车处于哪一步

因此应使用显式状态机。

### 7.2 阶段的四个部分

每个阶段至少包含：

```c
on_enter();       // 进入时执行一次
on_update();      // 阶段内周期执行
is_complete();    // 是否完成
on_timeout();     // 是否超时或失败
```

例如“沿线到 B 点”：

```text
进入：开启巡线，设置基础速度
更新：计算灰度误差并更新左右轮目标
完成：编码器距离超过最小阈值且检测到目标路口
超时：停止并进入故障状态
```

### 7.3 动作序列

将路线写成命令序列是有效的：

```text
前进 -> 右转判断 -> 原地右转 -> 巡线 -> 十字判断 -> 停车
```

但是命令序列必须配合：

- 每个阶段的参数
- 超时值
- 成功条件
- 失败条件
- 阶段日志
- 紧急停止动作

不能只用数字数组而没有枚举和说明。

### 7.4 编码器事件和传感器事件的组合

最可靠的完成条件通常是：

```text
距离达到最小值
且检测到目标传感器事件
或距离超过最大值
```

例如：

```text
if distance < min_distance:
    continue
elif line_event_detected:
    complete
elif distance > max_distance:
    fail_or_recover
```

这比只靠时间延时更抗电池电压和地面摩擦变化。

## 8. 电机控制的进一步升级

### 8.1 统一物理单位

推荐接口：

```c
Motor_SetTargetWheelSpeedMmps(left_mmps, right_mmps);
Motor_SetTargetRobotVelocity(vx_mmps, wz_radps);
```

不要在上层直接传“PWM 450”作为速度。PWM 是执行器输出，速度是运动目标，两者必须分开。

### 8.2 死区补偿

低 PWM 时电机可能不动，存在启动死区：

```text
PWM = sign(target) × (dead_zone + control_output)
```

但死区补偿不能破坏停车逻辑。目标速度接近 0 时必须清零 PWM 并复位控制器。

### 8.3 实际采样周期

控制器必须使用真实 `dt` 或稳定的固定周期。调试时要记录：

- 目标周期
- 实际周期
- 最大周期抖动
- 编码器增量
- 速度换算结果
- PWM 饱和次数

如果控制周期从 10 ms 变成 20 ms，PID 参数不应继续假定原来的周期。

## 9. 平衡控制和 LQR 入门

### 9.1 什么时候需要 LQR

普通巡线只需要电机速度环、巡线 PID 和角度控制。

倒立摆、球杆平衡等系统同时受到多个状态影响，单独控制角度可能不够。这时可以使用 LQR。

### 9.2 状态向量

典型状态为：

```text
x = [theta, theta_dot, position, velocity]^T
```

分别表示：

- `theta`：摆杆偏角
- `theta_dot`：摆杆角速度
- `position`：小车位置
- `velocity`：小车速度

### 9.3 系统辨识

不要凭感觉填写 LQR 参数。应先采集 CSV：

```text
时间,角度,角速度,位置,速度,PWM
```

离线拟合离散模型：

```text
x[k+1] = A × x[k] + B × u[k]
```

数据必须：

- 统一单位为 rad、rad/s、m、m/s
- 去掉明显异常样本
- 避免跨越被过滤样本进行错误配对
- 检查输入是否饱和
- 检查系统可控性

### 9.4 离散 LQR

给定权重矩阵 `Q` 和 `R`，求解离散 Riccati 方程得到 `K`：

```text
u = -K × (x - x_ref)
```

权重越大，系统越重视对应状态。例如：

- 增大 `Q_theta`：更重视摆杆角度
- 增大 `Q_pos`：更重视小车回到指定位置
- 增大 `R`：更节省控制输出，动作更保守

### 9.5 LQR 不能替代安全逻辑

LQR 输出必须有：

- PWM 限幅
- 角度安全范围
- 传感器失效检测
- 编码器异常检测
- 低电压保护
- 倒立失败后的停车或重新起立流程

当前项目先完成速度闭环和基础运动，再做 LQR。不要在电机方向、编码器符号和单位尚未验证时调 LQR。

## 10. 串口、调参和日志

### 10.1 中断只接收，主循环解析

串口中断中只做：

```text
读取 FIFO
写入环形缓冲区
设置收到数据标志
```

主循环再做：

- 帧头查找
- 长度判断
- CRC 校验
- 命令执行
- 参数范围检查
- 应答发送

不要在串口中断里打印大量日志或执行复杂控制。

### 10.2 推荐帧格式

```text
0xAA | version | length | command | sequence | payload | CRC16
```

至少支持：

- 读取参数
- 修改参数
- 保存参数
- 恢复默认值
- 启动/停止动作
- 请求状态
- 紧急停车

### 10.3 日志分级

```text
ERROR：故障和保护触发
WARN ：超时、传感器异常、PWM 饱和
INFO ：阶段切换、标定完成、任务开始结束
TRACE：高频控制数据，仅调试时打开
```

高频数据应使用二进制或紧凑 CSV，并通过发送队列异步发送，避免阻塞控制循环。

- 左右轮独立闭环

### 阶段 M4：灰度巡线

- 单通道读取
- 全通道读取

- 系统辨识
- LQR 或其他多变量控制
- 激光云台和参数化轨迹

## 13. 每个功能的完成标准

一个功能只有同时满足以下条件才算完成：

- 驱动接口和单位已经定义
- 单元或主机侧数据测试通过
- 低速实机测试通过
- 有至少一组原始数据记录
- 有异常和超时处理
- 有可调参数和默认值
- 没有把复杂逻辑塞进中断
- 能够重复构建
- 文档说明了如何复现

## 14. 给 AI 的项目协作规则

### 14.1 开始工作前

1. 阅读项目根目录的 `AGENTS.md`。
2. 识别当前工程的 MCU、SDK、编译器、SysConfig 和调试器。
3. 区分用户可编辑文件和生成文件。
4. 先读现有 `.syscfg`、头文件和调用链，不猜测宏名。
5. 如果任务涉及外部硬件，先确认引脚、电平、供电和数据手册。

### 14.2 修改配置时

- 只修改 `.syscfg`。
- 修改后运行 SysConfig 静态检查和隔离生成检查。
- 不直接编辑 `ti_msp_dl_config.c/h`。
- 不改变芯片、封装、SDK、编译器和调试器，除非用户明确要求。

### 14.3 修改控制算法时

- 先说明输入、输出、单位、采样周期和限幅。
- 保持传感器、控制器和执行器分层。
- 不把参数散落在多个函数中。
- 为状态转换添加完成条件、超时条件和故障动作。
- 对每个控制器保留可观测日志：目标、测量、误差、输出和饱和状态。

### 14.4 验证时

分别报告：

```text
静态检查：通过/失败
SysConfig 生成：通过/失败/有警告
编译：通过/失败
链接：通过/失败
串口或协议测试：通过/未测试
实机测试：通过/未测试
```

没有连接开发板和实际测量时，只能声称代码或构建验证通过，不能声称硬件功能已经验证。

## 15. 零基础学习路线

### 第 1 周：C 和 MCU 基础

- 变量、指针、结构体、枚举
- `volatile` 的含义
- GPIO 输入输出
- 中断和主循环
- PWM 基本概念

练习：LED、按键、蜂鸣器和串口打印。

### 第 2 周：电机和编码器

- 电机驱动方向
- PWM 占空比
- 编码器 A/B 相
- 计数差和速度
- 单轮 PID

练习：让轮子以 100、200、300 mm/s 运行并记录数据。

### 第 3 周：传感器和巡线

- ADC 和数字输入
- 灰度标定
- 加权平均
- PID 巡线
- 路口识别

练习：直线、弯道、十字和丢线恢复。

### 第 4 周：状态机和比赛动作

- 状态、动作、条件
- 里程事件
- 传感器事件
- 超时和故障
- 参数化路线

练习：完成固定路线、停车和重新启动。

### 第 5 周以后：融合控制

- IMU 角度保持
- 速度和姿态融合
- 记录实验数据
- 线性系统辨识
- LQR 基础
- 视觉和激光绘图接口

## 16. 最终原则

1. 先让硬件可观测，再让控制器变聪明。
2. 先完成单轮闭环，再做整车巡线。
3. 先完成固定路线，再做动态识别。
4. 先记录数据，再调整参数。
5. 先定义单位和周期，再写 PID。
6. 先定义状态和失败条件，再写赛题流程。
7. 控制中断保持短小，复杂处理放在主循环或任务中。
8. 生成文件由工具管理，业务代码由团队管理。
9. AI 可以辅助实现，但每个硬件假设都必须由原理图、引脚表或实测确认。
10. “能跑一次”不是完成，“能够解释、复现和测量”才是完成。
